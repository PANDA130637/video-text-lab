# 真实数据采集与实验协议

## 第一批数据

从 50–100 段自己拍摄或有明确使用许可的短视频开始。选择几个动作组合，分别真实执行 A→B 与 B→A，例如“拿起杯子→打开盒子”和“打开盒子→拿起杯子”。保持动作自然，尽量平衡人物、物体、背景和时长。

不要仅靠倒放真实视频制造反向动作：倒放可能产生明显的物理伪影。程序生成的反序色块只用于管线检查。

先用 6–12 段视频检查编码耗时、内存和标注格式。极少样本的训练结果仅作连通性验证。

## 标注格式

CSV 一行一个视频和一条描述，UTF-8 编码。列定义：

| 列 | 含义 |
|---|---|
| `id` | 唯一记录编号 |
| `group_id` | 来源视频或拍摄场次；同源切片与变体必须共享分组 |
| `split` | `train`、`val`、`test` |
| `video_path` | 绝对路径，或相对于 CSV 的路径；支持视频文件及帧图片目录 |
| `text` | 准确、简短的英文描述；保留动作和先后关系 |
| `semantic_id` | 本任务中可视为正确匹配的语义类别；等价描述/视频用同一个值 |
| `pair_id` | 同场景相反动作顺序的对照对；没有对照则留空 |
| `source` | 如 `real_recording` 或实际数据集名称；不要填写 `synthetic_control` |

`semantic_id` 不应简单等于每行 ID。如果多个视频都是“先拿杯子后开盒子”，且任务允许它们都匹配该描述，就使用同一个语义编号。反过来，描述含有不同物体、人物等细节且这些细节属于检索目标时，应区分其语义。

不需要让模型看到 `id`、文件名、`group_id` 或标签字符串；这些字段只用于组织数据和定义监督/评估。

## 划分与泄漏

在实验开始前固定划分；每个语义类别尽量在三个划分中都有样本，同一场次及其所有变体绝不能跨划分。拍摄时留出不同背景/日期/人物用于测试，并确保动作类别平衡。

程序会检查重复 ID、同组跨 split、同路径跨 split。它无法自动认出改名复制或视觉近重复，因此还需要人工检查来源。缓存指纹防止旧特征被误用，不等于自动去除数据泄漏。

CSV 样例只有 6 条，作用是说明格式，不足以支持可靠结论。

## 预先固定的对照

- 固定编码器、数据划分、训练轮数上限、验证标准。
- mean＋投影 vs. GRU＋投影，均使用相同缓存。
- 第一次用 8 帧；做帧数消融时使用不同缓存文件，例如 `features_4f.npz` 与 `features_8f.npz`。
- 至少记录 3 个训练种子；先在验证集做选择，再只汇报事先规定的测试结果。
- 真正判断容量因素时，增加参数量相近的无时序 MLP 基线。
- 记录 CLIP 文本特征能否区分两条顺序相反的描述；文本侧区分不开时，不能简单归因于视频模块。

## 要保留的证据

1. 数据来源、采集规则、类别和来源组数量。
2. 冻结编码器名称、版本、帧采样数、特征提取耗时。
3. 全部训练配置、随机种子、验证选择规则。
4. 视频→文本与文本→视频 Recall@K；明确各自候选数量。
5. 成对动作顺序判断及平分处理方式。
6. 失败样本：背景误导、动作遗漏、相似文字不可分、采样错过关键动作等。

某个改动没有改善也有研究价值：保留失败结果，检查假设，而不是挑选个别漂亮样例作为结论。

## 可以与不可以声称什么

- 完成合成实验后：可以说实现并验证了冻结特征上的检索训练、分组划分、多正例损失和时序对照。
- 完成真实数据实验后：根据真实测量结果说明小规模视频理解能力与限制。
- 不能据此声称完成视频大模型预训练、分布式训练或工业级视频生成系统。
